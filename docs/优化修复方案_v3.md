## 一、核实结论摘要（与上一版报告的差异）

| 项 | 上一版结论 | 核实后结论 |
| --- | --- | --- |
| A-3 | "init_db 阻塞端口绑定" | **维持原判**。uvicorn 源码（.venv 与 frozen 两条路径一致）为 `lifespan.startup()`（L105，含 `await init_db()`）→ `loop.create_server()`（L172），lifespan 先于端口绑定。收益表述改为"端口+ready 都提前" |
| C-2 | "每轮 50~250ms 系统提示重建" | **降级**。str.replace 为 C 层实现，60KB 整链 <1ms；`_last_base_system_prompt_by_sid` 变化检测已存在；`_read_agent_md`/skills/schema 均已缓存。收益忽略级 |
| C-2 补充 | 未提及 | **新增独立项**：首轮 `generate_openai_tools` 触发 10 个 lazy 工具 import（1~3s 一次性，位于 TTFT 关键路径）→ 需后台预热 |

## 二、方案原则

1. 只做已源码核实的项
2. 先消除"等待"再谈"提速"：A-1（5-15s）> B 段（2-4s）> C 段（首轮一次性 1-3s）
3. 懒加载的 trade-off 要配套预热（0.8.6 已将启动 import 推迟到首轮，必须补预热）
4. 不碰已验证已优化的部分（MCP 后台化、lazy import、各类缓存、首帧直发等）
5. 每项改动独立提交，单点问题单点 revert（15 项彼此无耦合，可任意裁剪）
