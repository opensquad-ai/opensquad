# OpenSquad 启动→首轮对话 优化修复方案（v2.1，已核实·融合版）

> 状态：已核实的优化方案存档（2026-08-03）
> 版本说明：v2 与 v3（另一 agent 方案）为同一批核实结论的产物，核心 12 项一一对应、零冲突。

> 依据：`docs/启动到首轮对话性能优化报告.md` 逐条核实（12/14 属实）+ uvicorn 源码实证 + 前几轮已落地优化清单。

## 〇、核实结论摘要（与上一版报告的差异）

| 项 | 上一版结论 | 核实后结论 |
|---|---|---|
| A-3 | "init_db 阻塞端口绑定" | **维持原判**。uvicorn 源码（.venv 与 frozen 两条路径一致）为 `lifespan.startup()`（L105，含 `await init_db()`）→ `loop.create_server()`（L172），lifespan 先于端口绑定。收益表述改为"端口+ready 都提前" |
| C-2 | "每轮 50~250ms 系统提示重建" | **降级**。str.replace 为 C 层实现，60KB 整链 <1ms；`_last_base_system_prompt_by_sid` 变化检测已存在；`_read_agent_md`/skills/schema 均已缓存。收益忽略级 |
| C-2 补充 | 未提及 | **新增独立项**：首轮 `generate_openai_tools` 触发 10 个 lazy 工具 import（1~3s 一次性，位于 TTFT 关键路径）→ 需后台预热 |

## 一、方案原则

1. 只做已源码核实的项
2. 先消除"等待"再谈"提速"：A-1（5-15s）> B 段（2-4s）> C 段（首轮一次性 1-3s）
3. 懒加载的 trade-off 要配套预热（0.8.6 已将启动 import 推迟到首轮，必须补预热）
4. 不碰已验证已优化的部分（MCP 后台化、lazy import、各类缓存、首帧直发等）
5. 每项改动独立提交，单点问题单点 revert（12 项彼此无耦合，可任意裁剪）

## 三、验证与回滚方案（每批合入前必须执行）

1. **语法检查**：`ruff check <改动文件>`（按项目配置）
2. **单测**：`pytest` 跑受影响模块测试；项目基线为 839 passed / 44 failed（44 为既有失败），**零新增为准**
3. **实测基线对比**：用 `scripts/timed_chat.py` 等跑 before/after，记录：CLI 命令→UI 可用秒数、agent_ready 秒数、首 token 秒数
4. **回归场景**：至少验证 ①`opensquad web` 二次启动直接秒开；②新建会话→发消息正常收流；③MCP 若启用，server 异常时 agent 仍可对话
5. **回滚**：每个改动点独立提交，单点问题单点 revert

## 四、明确"不做"清单（已核实无收益或已有缓存）

- ❌ C-2 每轮字符串重建优化——实测 <1ms/轮，收益忽略级
- ❌ `_read_agent_md` / skills / tools schema 缓存——已存在
- ❌ 首帧 debounce / token 统计 / MCP 后台化 / 工具 lazy——0.8.6 已落地
- ❌ docker/npm/pypi 分发链路——用户已明确不管
- ❌ playwright MCP 保持禁用，不动 MCP 配置（批次 1 第 4 项仅作防御性兜底）

## 六、执行顺序

```
批次 1（当天）：1 → 2 → 3 → 4 → 5
批次 2（次日）：6 → 7 → 8 → 9
批次 3（排期）：10 → 11 → 12 → 13（13 最后，需人工评审模板 + A/B）
```
