# OpenSquad 启动 → agent305 → 首轮对话 全链路性能优化报告

> 分析范围：`opensquad web` 从 cmd 启动 → Web UI 可用 → 启动 agent305 → 创建第一个新会话 → 发起第一轮对话。
> 数据来源：真实运行日志（`logs/agent305_restart.log`、`logs/agent301_start*.log`、`logs/importtime.log`）+ 源码链路分析。
> 生成日期：2026-08-03

---

### 3. 首轮对话固定输入

## 二、三段链路的瓶颈清单

### A. cmd 启动 → Web UI 可用（约 4–6s）


| #   | 瓶颈                                                                                         | 证据                                        | 性质    |
| --- | ------------------------------------------------------------------------------------------ | ----------------------------------------- | ----- |
| A1  | Gateway 模块导入链累计 3.4s，`_main`/`collab_board`/`launcher_handler` 均在绑定端口前 eager import        | `main.py:73-83`、`routes/__init__.py:10`   | 代码    |
| A2  | ReadinessMiddleware 503 窗口：`/api/groups`、`/api/ai-web/agents` 不在 lite 前缀，要等 full-ready 才可用 | `main.py:192-199`、`_finish_heavy_startup` | 代码    |
| A3  | `_admin/_market` 懒加载（约 1.1s import）被前端登录后的 `preloadSystemConfig()` 提前触发，收益被抵消              | `App.tsx:176-183`、`LazyRoutesMiddleware`  | 代码/前端 |
| A4  | `_setup_local_mode` 同步跑子进程（0.3–2s）                                                         | `start_cmd.py:411-417`                    | CLI   |
| A5  | `_kill_port_owners` 无条件跑 `netstat -ano`（0.2–1s），即使端口空闲                                     | `start_cmd.py:519/305`                    | CLI   |
| A6  | `_find_python` 每次 subprocess 探测（0.2–0.5s）                                                  | `start_cmd.py:38-62`                      | CLI   |
| A7  | lifespan 内 `warm_all_task_managers` + `init_db` 阻塞端口绑定                                     | `main.py:292-314`、`database.py:102-117`   | 代码    |
| A8  | 前端登录后 `getRegistrationStatus()` 串行等待 `getMe/loadGroups`；恢复会话带 100ms setTimeout             | `App.tsx:434-480`                         | 前端    |


### B. UI 启动 agent305 → 就绪（核心 2.9s，完全 9.9s）


| #   | 瓶颈                                                                                         | 证据                                                | 实测             |
| --- | ------------------------------------------------------------------------------------------ | ------------------------------------------------- | -------------- |
| B1  | **MCP 服务器连接 6.6s**：`playwright` server 用 `npx @playwright/mcp@latest`，冷启动需解析/下载包再启动子进程     | `mcp_config.json`、`mcp_adapter.py:359-373`        | **最大单项**       |
| B2  | **插件加载 1.5–1.8s**：逐个 import 插件模块 + 每次重写 plugin.json                                        | `plugin_manager.py` `discover_and_load`           | agent_ready 主导 |
| B3  | 模块 import 链（agents_boot → runner → tools 11 个 MANDATORY 同步 import，含 psutil/bridge）约 1.5–3s | `agents_boot.py:302-314`、`tools/__init__.py:9-30` | 冷启动固定成本        |
| B4  | 主协程 `await extension_task` + `await mcp_task`，MCP 未完成前不继续（群聊 bridge 推迟）                    | `agents_boot.py:1075/1082`                        | 阻塞             |
| B5  | `setup_connections` 先同步 `_setup_web_server`（import uvicorn + 端口探测）再建 gateway 连接            | `agent_boot_phases.py:125-126`                    | 阻塞             |
| B6  | long_memory 3.2s + jieba 1.8s（已后台化，但占 CPU/GIL）                                             | `agent_boot_phases.py:497-564`                    | 后台             |
| B7  | config.json 全链路读 3 次（launcher + agents_boot + AgentRunner）+ 重复 Pydantic 校验                 | `_agent_handler.py:108`、`runner.py:254-259`       | 冗余             |


> 注意：agent 注册 gateway 只需 ~0.4s（agent_runtime_ready），**UI 上 agent 很快显示在线、可接收消息**；2.9s 的 agent_ready 是"插件+技能"就绪，6.6s 的 MCP 是"工具完备"就绪。真正拖慢首轮的是 B1/B2 与 C 段。

### C. 新会话创建 → 首轮 LLM 响应（TTFT）


| #   | 瓶颈                                                                                       | 证据                                                          | 影响                  |
| --- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ------------------- |
| C1  | **超大系统提示词（~3 万 token）prefill**：base_fc.md 33 个 include 展开 ~68KB，叠加 skills/MCP/collab 注入  | `src/prompts/base_fc.md`、`context_builder.py:142`           | **TTFT 最大单项 2–10s** |
| C2  | `_setup_prompt` 每轮全量重建系统提示（含 `_read_agent_md` 每次读文件、`generate_openai_tools` 首次生成 schema） | `context_builder.py:175/230`、`context_base.py:125`          | 每轮 50–300ms         |
| C3  | 冷启动等待：agent 未就绪时用户 WS 最多等 3s（超时 1013）；前端在 agent_ready 前禁输入                               | `websocket.py:486-505`                                      | 首个会话体验              |
| C4  | 每新会话 `_clone_chat_api` 新建 ChatAPI，client/tokenizer 懒加载首次触发全量 token 重算                    | `session_dispatcher.py:23`、`chat_api.py:2028`               | 50–500ms            |
| C5  | `session_model.persist` 同步双文件写盘（首轮带 model_card 时触发）                                      | `session_model.py:82/147`、`session_manager.py:302-333`      | 5–50ms              |
| C6  | 流式回传 30ms debounce + 双层 JSON 序列化                                                         | `gateway_adapter.py:911`、`sdk.py:404`                       | TTFT +30ms          |
| C7  | 超时/重试：`timeout=120s` 是总超时非首字节；`max_stream_retries=6`，慢 prefill 可触发重试退避叠加                 | `chat_api.py:2012/2200-2214`、`llm_call_orchestrator.py:124` | 异常时盲等               |
| C8  | `start_new_session` 同步存档旧会话（全量 JSON 写 history）                                           | `session_manager.py:1097/484`                               | 10–100ms            |


> **好消息**：网络跳数低（前向/回向各 1 跳 WS），Gateway 消息路径无同步持久化阻塞（0.5s 异步批写），工具 schema 有缓存，token 计数有增量缓存。

## 三、优化建议（按投入产出比分级）

### P0 — 快速见效（配置/环境，不改或极少改代码）


| #   | 措施                                                                                                                    | 目标瓶颈  | 预估收益                        |
| --- | --------------------------------------------------------------------------------------------------------------------- | ----- | --------------------------- |
| 1   | **MCP playwright 预装 + 快速失败**：把 `npx @playwright/mcp@latest` 改为全局/本地已安装命令；或给该 server 设短 timeout + 失败后后台重连，不让 6.6s 阻塞就绪 | B1    | 完全就绪 **-6s**                |
| 2   | **精简 agent305 插件/工具**：`config.tools` 只留常用（如关掉 vision/step_voice/whisper 等），减少插件加载与工具定义                                | B2、C1 | 就绪 **-0.5~1.5s**；prefill 略降 |
| 3   | **精简系统提示词模板**：base_fc.md 的 33 个 include 中砍掉历史遗留/低频规则，压缩到 ~一半                                                          | C1    | TTFT **-1~5s**              |
| 4   | **保持 built dist 模式**（`opensquad start` 已自动跳过 Vite），避免 npm/Vite 冷启动                                                    | A 段   | 已生效                         |
| 5   | 首次使用前**预热**：`npm i -g @playwright/mcp`、`npx playwright install`，消除冷启动下载                                               | B1    | 就绪 **-3~6s**（一次性）           |


### P1 — 低成本代码改动（单项 ≤ 半天）


| #   | 措施                                                                                                            | 目标瓶颈     | 预估收益              |
| --- | ------------------------------------------------------------------------------------------------------------- | -------- | ----------------- |
| 1   | **主协程不 `await mcp_task**`：MCP 全后台，agent chat-ready 即完全可对话；group_chat_bridge 也独立 task                          | B4       | 可用提前 **1~5s**     |
| 2   | **MCP per-server 启动超时（如 5s）+ 自动重连**                                                                           | B1       | 单慢 server 不再拖全量   |
| 3   | **工具模块 lazy import**：MANDATORY_TOOLS 11 个改为首次调用时 import（ToolRegistry 支持 wrapper）；`tools/__init__.py` 取消 eager | B3       | 冷启动 **-0.8~1.5s** |
| 4   | **web server 后台化 + gateway 注册提前**：`_setup_web_server` 改 create_task，两者无依赖                                     | B5       | 注册提前 **0.3~0.6s** |
| 5   | **系统提示增量构建**：`_read_agent_md` 加 mtime 缓存；稳定块复用字符串，只重建变化块                                                      | C2       | 每轮 **-50~250ms**  |
| 6   | **流式首帧即时 flush**（首 chunk 不等 30ms debounce）                                                                    | C6       | TTFT **-30ms**    |
| 7   | `**session_model.persist` 异步化/去双写**；New Chat 存档走异步批写                                                          | C5、C8    | 首轮 **-5~50ms**    |
| 8   | **clone ChatAPI 共享 client/tokenizer**（只读资源继承根实例）                                                              | C4       | 新会话 **-50~500ms** |
| 9   | **独立首字节超时 + 已有 chunk 不重试**                                                                                    | C7       | 异常秒级反馈            |
| 10  | **CLI 微优化**：`_kill_port_owners` 先 50ms 端口探测再 netstat；`_find_python` 缓存；`_setup_local_mode` 条件跳过               | A4/A5/A6 | 命令→就绪 **-0.5~3s** |
| 11  | `**/api/groups`、`/api/ai-web/agents` 纳入 lite 前缀**                                                             | A2       | UI 首屏提前 **~1s**   |
| 12  | `**_admin` 顶层 import 移入函数内**；`preloadSystemConfig` 走轻量路由                                                      | A3       | 首开设置不卡 1.1s       |
| 13  | **config.json 单次读取**：AgentRunner 复用已读 config，合并两套校验                                                           | B7       | **-50~150ms**     |
| 14  | **插件/技能缓存**：plugin.json 元数据无变化不落盘；技能目录扫描结果缓存                                                                  | B2       | 就绪 **-100~500ms** |


### P2 — 架构调整（≥ 1 天）


| #   | 措施                                                                                            | 目标   | 收益                |
| --- | --------------------------------------------------------------------------------------------- | ---- | ----------------- |
| 1   | Gateway 路由全面懒加载（`_main` 也改 PEP 562 `__getattr__`，重模块函数内 import）                               | A1   | 绑定前 **-0.5~1.0s** |
| 2   | **就绪状态分级**：`chat-ready`（可对话）vs `full-ready`（MCP/插件完备），UI 展示"启动中/工具加载中"进度而非静默                  | B、C3 | 体验透明              |
| 3   | **启用 LLM 前缀缓存**（OpenAI prompt cache / Claude `cache_control`）：稳定系统提示打 cache，长会话复用             | C1   | 长会话 TTFT 大幅下降     |
| 4   | **前端请求链并行**：`getRegistrationStatus` 与 token 恢复并行；预取上次活跃群消息；model-presets refresh 延后/disk-only | A8   | 首屏少 1–2 RTT       |
| 5   | `_setup_prompt` 与工具循环解耦：工具 schema 复用、动态块缓存                                                    | C2   | 多轮任务收益放大          |

## 四、预期总收益


| 场景                       | 当前典型                 | 优化后预期                          |
| ------------------------ | -------------------- | ------------------------------ |
| `opensquad web` → UI 可操作 | 4–6s                 | 2.5–4s（P1-10/11/12 + P0-4）     |
| UI 启动 agent305 → 插件就绪    | 2.9s                 | 1.5–2s（P1-1/3/4）               |
| agent305 完全可用（含 MCP）     | 9.9s                 | 3.5–5s（P0-1/5 + P1-2）          |
| 首轮对话首 token（TTFT）        | 模型推理 + 2~10s prefill | prefill 砍半 + 首帧即时（P0-3 + P1-6） |
| 每轮消息系统开销                 | 50–300ms             | 50ms 以内（P1-5/7/8）              |


**最高 ROI 的前三件事**：① MCP playwright 预装/后台化（-6s 就绪）；② 精简 base_fc.md 系统提示 + 启用前缀缓存（-1~~5s TTFT）；③ 工具模块 lazy import + 主协程不等 MCP（agent 可对话提前 1~~5s）。
